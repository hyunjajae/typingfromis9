# fromis_9 TYPING 🎧⌨️

프로미스나인 팬을 위한 웹 타이핑 게임입니다.
빌드 도구·프레임워크 없이 **순수 HTML + CSS + JavaScript**로만 만들어져서,
폴더를 그대로 GitHub Pages에 올리면 바로 동작합니다.

### 세 가지 모드

| 모드 | 설명 |
|---|---|
| **01 응원법 외우기** | 마이크에 대고 **직접 외치거나** 키보드로 쳐서 응원법을 익힙니다. 노래는 멈추지 않고, 응원 구간이 뜨면 박자를 맞춰야 성공. 가사가 같이 흘러서 노래를 따라갈 수 있습니다. |
| **02 가사 타이핑** | 노래를 들으며 흘러나오는 가사를 실시간으로 따라 칩니다. 정확도·타수(CPM)·소요 시간을 기록합니다. |
| **03 인트로 퀴즈** | 여러 곡의 도입부가 순서대로 재생됩니다. **객관식**(보기 4개 중 고르기) 또는 **주관식**(제목 타이핑) 으로 답하는 **스피드런**. |

각 모드는 `data/features.js` 로 하나씩 켜고 끌 수 있습니다.

한글은 자모가 실시간으로 조합되기 때문에(ㅇ → 아 → 안 → 안녕) 그냥 글자를 비교하면
오판정이 납니다. 이 게임은 IME 조합 이벤트(`compositionstart` / `compositionend`)를 사용해서
**조합이 끝난 글자만 정답 판정**하고, 조합 중인 글자는 자모 단위로 "앞부분이 맞는지"만 확인합니다.

## 1. 로컬에서 실행하는 방법

### 가장 간단한 방법
`index.html` 파일을 더블클릭하면 브라우저에서 바로 열립니다.

### 권장 방법 (로컬 서버)
mp3 재생이나 브라우저 보안 정책 때문에 문제가 생길 수 있어서, 작은 웹서버를 띄우는 걸 권합니다.
PowerShell을 열고 아래 명령을 실행하세요.

**Python이 설치돼 있다면:**

```bash
cd "$HOME\Desktop\fromis9-typing"; python -m http.server 5660
```

**Node.js를 쓴다면:**

```bash
cd "$HOME\Desktop\fromis9-typing"; npx.cmd serve -l 5660
```

그다음 브라우저에서 **http://localhost:5660** 으로 접속하면 됩니다.
서버를 끄려면 그 창에서 `Ctrl + C` 를 누르세요.

## 2. `audio` 폴더에 mp3 넣는 법

1. `audio/` 폴더에 mp3 파일을 그대로 복사해 넣습니다.
2. 파일 이름은 **영어 소문자 + 숫자**로 짓는 걸 권합니다.
   (한글이나 공백이 들어간 파일명은 GitHub Pages에서 가끔 깨집니다.)
   - 좋은 예: `dm.mp3`, `wego.mp3`, `talkandtalk.mp3`
   - 피할 이름: `두근두근 (DKDK).mp3`, `Feel Good (192k).mp3`
3. `data/songs.js` 의 `audio` 값을 그 파일명과 똑같이 맞춰줍니다.

```js
audio: "audio/dm.mp3",
```

### `audio/intro/` — 퀴즈용 짧은 인트로 파일

인트로 퀴즈는 도입부 6초만 들려주면 되는데, 전체 mp3 를 걸면 브라우저가
**곡 하나를 통째로(약 4MB) 내려받습니다.** 16곡이면 한 판에 70MB 예요.

그래서 `audio/intro/` 에 **6.5초짜리 짧은 파일**을 따로 두고 퀴즈는 그걸 씁니다.

| | 퀴즈 1회 완주 시 내려받는 양 |
|---|---|
| 전체 mp3 사용 | 70.5 MB |
| **인트로 파일 사용** | **1.6 MB** (98% 감소) |

- 파일 이름은 **곡의 `id` 와 같아야 합니다.** 예) `id: "dm"` → `audio/intro/dm.mp3`
- **없으면 자동으로 전체 mp3 에서 구간 재생합니다.** 그러니 곡을 추가할 때
  인트로 파일을 안 만들어도 정상 동작합니다. (용량만 더 쓸 뿐이에요)

**새 곡의 인트로 파일 만드는 법** (ffmpeg 필요)

```bash
ffmpeg -ss 0 -t 6.5 -i audio/새곡.mp3 -c:a libmp3lame -b:a 128k audio/intro/새곡id.mp3
```

`-ss 0` 은 시작 지점, `-t 6.5` 는 길이입니다.
`data/songs.js` 의 `intro: { start: 12, ... }` 처럼 시작을 바꿨다면 `-ss 12` 로 맞춰주세요.

> **mp3가 아직 없어도 괜찮습니다.**
> 파일을 못 찾으면 화면에 "오디오 파일 없음" 배지만 뜨고, 타이핑 게임은 그대로 동작합니다.

> ✅ **지금 15곡의 mp3 · 앨범 커버가 이미 들어가 있습니다.**
> `fromis9-album-player` 프로젝트(`src/config.js`)에서 가져온 것이라
> 곡 ↔ 앨범 매핑도 검증된 값입니다.

> ⚠️ **저작권 주의**
> 음원 · 가사 · 앨범 커버는 모두 저작권이 있는 자료입니다. 이것들을 넣은 상태로 GitHub에
> 공개(public) 저장소로 올리면 문제가 될 수 있습니다.
> mp3는 개인 PC에서만 쓰고, 공개 배포할 때는 `.gitignore` 로 제외하는 걸 권합니다.
> (이 프로젝트에는 `audio/*.mp3` 를 제외하는 `.gitignore` 가 이미 들어 있습니다.)

## 2-b. `covers` 폴더 — 앨범 커버 이미지

곡 선택 화면의 썸네일과, 가사 타이핑 화면의 흐린 배경에 쓰이는 이미지입니다.

1. `covers/` 폴더에 이미지를 넣습니다. **정사각형(1:1)** 이미지가 가장 예쁘게 나옵니다.
2. `data/songs.js` 의 `cover` 값을 파일 경로로 맞춰줍니다.

```js
cover: "covers/midnight-guest.jpg",
```

- `cover: ""` 로 비워두면 곡 제목 앞 두 글자가 들어간 **대체 썸네일**이 자동으로 표시됩니다.
- 파일을 못 찾아도 게임은 깨지지 않고 대체 썸네일로 넘어갑니다.

> 💡 **작은 커버 (`covers/thumb/`)**
> 시작 화면의 커버 띠(108px)와 곡 목록(약 200px)에서는 커버가 작게 나오므로,
> 800px 원본 대신 `covers/thumb/` 의 **400px 짜리**를 씁니다. (16장 1.7MB → 0.45MB)
> 인트로 퀴즈의 정답 공개 화면처럼 크게 보여줘야 하는 곳은 원본을 그대로 씁니다.
>
> **곡을 새로 추가할 때 썸네일은 안 만들어도 됩니다.** 없으면 자동으로 원본을 씁니다.
- 이미지가 너무 크면 사이트가 느려집니다. **가로세로 800px 정도**로 줄여서 넣으세요.
  (지금 들어있는 15장은 이미 800×800으로 줄여둔 상태입니다. 총 1.6MB)

> 인트로 퀴즈 화면에는 커버를 **일부러 표시하지 않습니다.** 정답이 보이면 안 되니까요.

## 2-c. `images` 폴더 — 로고

| 파일 | 쓰이는 곳 |
|---|---|
| `images/logo.png` | 상단바 · 시작 화면 문구 앞의 fromis_9 하트 로고 |

- **256 × 256px, 배경이 투명한 PNG**여야 합니다.
- 바꾸고 싶으면 같은 이름으로 덮어쓰면 됩니다.

### 결과 화면 사진 (`images/result/`)

게임을 한 판 끝낼 때마다 **무작위로 한 장**이 뜹니다. 지금 25장이 들어 있습니다.

- **비율은 아무래도 상관없습니다.** 가로·세로·정사각형 다 됩니다.
  사진을 잘라내지 않고 **통째로** 보여주고, 뒤에 같은 사진을 흐리게 깔아서 빈 공간을 채웁니다.
  그래서 **얼굴이 잘릴 일이 없습니다.**
- 한 장당 **500KB 이하**를 권합니다. (결과 화면마다 한 장씩 받아오니까요)
- 같은 사진이 연달아 나오지 않도록 직전에 쓴 건 피합니다.

**사진 추가하는 법**

1. `images/result/` 폴더에 파일을 넣습니다.
2. `data/result-art.js` 목록에 한 줄 추가합니다.

```js
const RESULT_ART = [
  "images/result/chaeyoung.jpeg",
  "images/result/새로운사진.jpg",     // ← 이렇게
];
```

빼고 싶으면 그 줄만 지우면 됩니다. (파일은 안 지워도 돼요)

### 시작 화면은 이미지를 더 넣을 필요가 없습니다

| 요소 | 어디서 오나 |
|---|---|
| 앨범 커버 띠 (천천히 흐르는 줄) | `covers/` 폴더의 앨범 커버를 **자동으로** 씁니다 |
| 모드 카드 01/02 미리보기 | 실제 게임 화면을 **HTML/CSS 로 그려냅니다** |

카드 미리보기를 스크린샷 이미지가 아니라 코드로 그린 이유는,
확대해도 안 깨지고 · 다크 모드에 자동 대응하고 · 게임 디자인을 바꾸면 미리보기도
같이 바뀌기 때문입니다. (스크린샷은 디자인을 고칠 때마다 다시 찍어야 합니다)

## 3. `data/songs.js` 에 곡 · 가사 · 인트로 구간 추가하는 법

곡을 추가하려면 **이 파일 하나만** 고치면 됩니다. 다른 파일은 건드릴 필요가 없어요.

### 곡 하나의 형태

```js
{
  id: "dm",                          // 고유 이름 (영어/숫자, 겹치면 안 됨)
  title: "DM",                       // 인트로 퀴즈의 정답
  titleAliases: ["디엠"],            // 정답으로 같이 인정할 표기 (없으면 생략 가능)
  album: "Midnight Guest",           // 곡 선택 화면에 작게 표시 (선택)
  audio: "audio/dm.mp3",             // mp3 경로
  intro: { start: 0, duration: 6 },  // 인트로 퀴즈에서 0초부터 6초간 재생
  lyrics: [
    { time: 12.5, text: "가사 첫 줄" },
    { time: 16.0, text: "가사 둘째 줄" }
  ]
}
```

### 각 항목 설명

- **`title` / `titleAliases`** — 인트로 퀴즈의 정답 판정은 **아주 너그럽습니다.**

  | 무시하는 것 | 예 |
  |---|---|
  | 대소문자 · 공백 · 특수문자 | `Talk & Talk` = `talk talk` = `talktalk` = `TALK&TALK` |
  | 된소리 · 거센소리 (ㅃㅍ→ㅂ, ㄲㅋ→ㄱ, ㅉㅊ→ㅈ …) | `필굿` = `삘굿` |
  | 받침 소리 (한국어 끝소리 규칙: ㅅㅆㅈㅊㅌㅎ→ㄷ) | `필굿` = `필굳` |
  | ㅐ/ㅔ/ㅒ/ㅖ, ㅚ/ㅙ/ㅞ, ㅢ/ㅣ | `톡앤톡` = `톡엔톡` |
  | 외래어 반모음 (ㅑㅕㅛㅠ → ㅏㅓㅗㅜ) | `슈퍼소닉` = `수퍼소닉` |

  즉 **`titleAliases`에 `"필굿"` 하나만 넣어두면**
  `삘굿` · `필 굿` · `삘 굿` · `필굳` · `삘굳` 이 전부 정답 처리됩니다.

  영어 제목에는 **한글 발음 표기를 하나만** 넣어주면 충분합니다.
  ```js
  titleAliases: ["필굿"],
  ```

  > ⚠️ 가사 타이핑 모드는 이 규칙을 **쓰지 않습니다.** 거기선 한 글자도 안 틀리게 정확히 판정해요.

- **`intro: { start, duration }`** — 인트로 퀴즈에서 재생할 구간(초).
  `{ start: 12, duration: 5 }` 라면 12초 지점부터 5초간만 재생하고 정확히 멈춥니다.
  도입부가 밋밋한 곡은 후렴 앞부분을 잘라 쓰면 난이도 조절이 됩니다.

- **`lyrics`** — 가사 타이핑 모드용. `time` 은 **그 줄이 시작되는 초**입니다.
  `12.5` 처럼 소수점도 쓸 수 있습니다.
  - 한 줄이 너무 길면 두 줄로 나누는 게 치기 편합니다 (한 줄 20~30자 권장).
  - 한글 / 영어 / 숫자 / 문장부호가 섞여 있어도 그대로 판정됩니다.

### ⭐ 가사 시간(`time`) 은 손으로 안 적어도 됩니다 — 타임코드 도구 사용

시간을 하나하나 재서 적을 필요 없이, **노래 들으면서 스페이스바만 누르면** 됩니다.

1. 시작 화면 맨 아래 **"🎚️ 가사 타임코드 찍는 도구 열기"** 를 누릅니다.
   (또는 주소창에 `http://localhost:5660/lyrics-timer.html`)
2. **Step 1** — 드롭다운에서 **곡을 고릅니다.** `audio/` 폴더에 들어있는 곡이 전부 나옵니다.
   - 이미 가사가 있는 곡은 `✓ 가사 6줄` 처럼 표시되고, 고르면 **기존 가사를 자동으로 불러옵니다.**
     (시간만 다시 찍고 싶을 때 편해요)
   - 목록에 없는 mp3는 아래 *"목록에 없는 mp3를 직접 고르기"* 를 펼쳐서 파일로 열 수 있습니다.
3. **Step 2** — 가사를 통째로 붙여넣습니다. 한 줄에 한 문장, 빈 줄은 자동 무시.
4. **Step 3** — `▶ 재생` 을 누르고, 가사 한 줄이 **시작되는 순간마다 스페이스바**를 칩니다.
5. **Step 5** — 완성된 `lyrics: [...]` 를 복사해서 `data/songs.js` 에 붙여넣으면 끝.

| 키 / 버튼 | 동작 |
|---|---|
| `Space` | 지금 재생 위치를 다음 줄의 시작 시간으로 찍기 |
| `Backspace` | 방금 찍은 것 취소 |
| `P` | 재생 / 정지 |
| `⟲ 5초 뒤로` | 놓쳤을 때 조금 되감기 |
| `-0.5 / -0.1 / +0.1 / +0.5` | 찍은 시간 미세조정 |

> 💡 사람 반응속도 때문에 보통 **0.1~0.3초 늦게** 찍힙니다.
> 다 찍은 뒤 전체적으로 `-0.1` 씩 당겨주면 더 잘 맞아요.

### 곡 순서 바꾸기

곡 선택 화면과 앨범 커버 띠에 나오는 순서는 `data/songs.js` **맨 위의 `SONG_ORDER`** 가 정합니다.

```js
const SONG_ORDER = [
  "vitaminme",
  "whitememories",
  "likeyoubetter",
  ...
];
```

여기 `id` 순서만 바꾸면 화면 순서가 바뀝니다. 아래의 긴 `SONGS` 배열은 건드릴 필요가 없어요.
목록에 안 적힌 곡은 맨 뒤에 자동으로 붙습니다.
(인트로 퀴즈는 매번 무작위로 섞이므로 이 순서와 무관합니다.)

### 응원법도 같은 도구로 찍습니다

두 도구 모두 위쪽에 **`가사` / `응원법`** 버튼이 있습니다. 누르면 대상이 바뀝니다.

| 고른 것 | 나오는 결과 | 붙여넣을 곳 |
|---|---|---|
| 가사 | `lyrics: [...]` | 곡의 `lyrics` |
| 응원법 | `chants: [...]` | 곡의 `chants` |

찍는 방법은 완전히 같습니다. **응원을 외치기 시작하는 순간**마다 스페이스바를 누르면 됩니다.

```js
{
  id: "dm",
  ...
  lyrics: [ ... ],
  chants: [
    { time: 12.40, text: "이새롬 송하영 박지원 노지선" },
    { time: 18.95, text: "이서연 이채영 이나경 백지헌" }
  ]
}
```

`chants` 가 없는 곡은 응원법 모드에 안 나옵니다.

### 도구 여는 법 — `도구 열기.bat` 을 더블클릭

프로젝트 폴더의 **`도구 열기.bat`** 을 더블클릭하면 서버가 켜지고 브라우저에 도구 목록이 열립니다.
작업이 끝나면 검은 창에서 아무 키나 누르면 서버가 꺼집니다.

> ⚠️ **`lyrics-tuner.html` 파일을 직접 더블클릭하면 노래가 안 나옵니다.**
> 브라우저가 보안상 `file://` 상태에서는 mp3 읽기를 막기 때문입니다.
> 반드시 `도구 열기.bat` 으로 여세요. (직접 열면 화면에 빨간 경고가 뜹니다)

인터넷에 올라간 도구도 쓸 수 있습니다.

| | 주소 | 읽는 곡 데이터 |
|---|---|---|
| **로컬** (권장) | `도구 열기.bat` | **지금 내 PC의** `songs.js` |
| 배포본 | `typingfromis9.kr/lyrics-tuner` | **푸시된** `songs.js` |

미세조정은 *고치고 → 확인하고 → 또 고치는* 작업이라 **로컬을 쓰셔야** 합니다.
배포본은 푸시해야 반영되므로 확인용으로만 쓰세요.

### ⭐ 타이밍이 미세하게 안 맞을 때 — 미세조정 도구

`lyrics-tuner.html` (주소창에 `http://localhost:5660/lyrics-tuner.html`)

타임코드 도구(`lyrics-timer.html`)로 찍은 시각은 사람 반응속도 때문에 보통 조금씩 늦습니다.
이 도구는 **한 줄씩 반복해서 들으며** 0.05초 단위로 다듬는 용도입니다.

1. 곡을 고릅니다. (mp3를 통째로 받아오므로 몇 초 걸립니다)
2. 줄을 클릭하면 그 줄이 **반복 재생**됩니다.
3. 소리를 들으며 `←` `→` 로 -0.05 / +0.05초씩 밉니다. **조절하는 즉시 새 지점부터 다시 들려줍니다.**
4. 다 되면 아래 코드를 복사해서 `data/songs.js` 에 붙여넣습니다.

| 키 | 동작 |
|---|---|
| `Space` | 재생 / 정지 |
| `←` `→` | 현재 줄 -0.05초 / +0.05초 |
| `↑` `↓` | 이전 줄 / 다음 줄 |

- **전체 -0.1s / +0.1s** — 곡 전체가 통째로 밀렸을 때 한 번에 당기거나 미룹니다.
- **미리듣기 길이 / 앞 여유** — 줄 시작 얼마 전부터 몇 초를 들을지 정합니다.
  앞 여유를 0.5초로 두면 "가사가 시작되기 직전"이 들려서 맞추기 쉽습니다.
- 바꾼 줄은 **빨간색**으로 표시되고, `되돌리기` 로 원래대로 되돌립니다.

### 특수한 경우

- **가사 모드에는 안 넣고 퀴즈에만 내고 싶은 곡** → `lyrics: []` 로 비워두세요.
  곡 선택 화면에는 안 뜨고 인트로 퀴즈에만 출제됩니다.
- **곡을 빼고 싶을 때** → 해당 `{ ... }` 블록을 통째로 지우거나 앞뒤를 `/* */` 로 감싸세요.

> 💡 `localhost` 로 열었을 때는 파일을 저장하고 **F5만 눌러도 바로 반영**됩니다.
> (브라우저가 옛날 파일을 캐시하지 않도록 `index.html` 에 처리를 해뒀습니다.
>  GitHub Pages 에 올린 뒤에는 캐시를 정상적으로 써서 빠르게 열립니다.)
> 그래도 이상하면 **`Ctrl + Shift + R`** (강력 새로고침)을 눌러보세요.

## 3-a. 기능 하나씩 공개하기 (`data/features.js`)

릴스를 순서대로 올리면서 기능을 하나씩 공개하기 위한 스위치입니다.
**코드는 전부 그대로 있고, 화면에 보일지만 정합니다.**

```js
const FEATURES = {
  autoWait: false,   // 노래 맞춰주기
  quiz: false        // 인트로 퀴즈
};
```

공개할 때가 되면 그 줄을 `false` → `true` 로 바꾸고 저장한 뒤 push 하면 됩니다.

| 릴스 | 바꿀 것 | 사이트에서 생기는 일 |
|---|---|---|
| 1편 · 타이핑 게임 | (지금 상태) | 가사 타이핑만 |
| 2편 · 기다려주기 | `autoWait: true` | 오디오 바에 "노래 맞춰주기" 버튼이 생기고, 노래가 기다려줍니다 |
| 3편 · 인트로 퀴즈 | `quiz: true` | 시작 화면에 "02 인트로 퀴즈" 카드가 생기고, 랭킹에 퀴즈 탭이 생깁니다 |

**`false` 일 때 감춰지는 것**

- `autoWait` — 오디오 바의 "노래 맞춰주기" 버튼, "기다리는 중…" 표시.
  기능 자체도 꺼져서 노래가 기다려주지 않고 계속 흘러갑니다.
- `quiz` — 시작 화면의 02 카드, 랭킹 화면의 "인트로 퀴즈" 탭.
  카드가 하나만 남으면 자동으로 가운데 1단으로 배치됩니다.

> 감추는 것뿐이라 언제든 되돌릴 수 있습니다. 켜면 원래대로 전부 살아납니다.

## 3-b. 랭킹 붙이기 (Supabase) — 처음부터 끝까지

여러 사람 기록을 모아서 순위를 매기는 기능입니다. **설정 전에는 랭킹 관련 화면이 전부 숨겨져 있고**,
게임은 지금까지처럼 똑같이 동작합니다. 천천히 하셔도 돼요.

### 왜 Supabase 가 필요한가요?

GitHub Pages 는 **파일을 보여주기만** 하는 서버입니다. 데이터를 받아서 저장해 두는 기능이 없어요.
그래서 "저장하는 일"만 Supabase 라는 무료 서비스에 맡깁니다.

```
[GitHub Pages]  ← 지금 이 사이트 (그대로 둡니다)
      ↕
[Supabase]      ← 기록만 여기에 저장
```

---

### 1단계 · 가입하고 프로젝트 만들기

1. https://supabase.com 접속 → 오른쪽 위 **Start your project**
2. GitHub 계정으로 로그인 (이미 있으니 제일 편해요)
3. **New project** 클릭
4. 입력할 것
   - **Name**: `fromis9-typing` (아무거나)
   - **Database Password**: 아무거나 길게. **꼭 어딘가 적어두세요.** (나중에 쓸 일은 거의 없습니다)
   - **Region**: `Northeast Asia (Seoul)` 선택 ← 한국이라 제일 빠릅니다
5. **Create new project** → 준비되는 데 1~2분 걸립니다

---

### 2단계 · 기록을 담을 표(테이블) 만들기

1. 왼쪽 메뉴에서 **SQL Editor** (아이콘이 `>_` 모양) 클릭
2. **New query** 클릭
3. 아래를 **통째로 복사해서 붙여넣고** 오른쪽 아래 **Run** 을 누르세요

```sql
-- 기록을 담을 표
create table scores (
  id          bigint generated always as identity primary key,
  created_at  timestamptz not null default now(),
  nickname    text    not null,
  mode        text    not null,
  song_id     text,
  cpm         int,
  accuracy    int,
  seconds     numeric,
  misses      int,

  -- 말도 안 되는 값이 들어오는 걸 막는 규칙들
  constraint nickname_길이  check (char_length(nickname) between 2 and 12),
  constraint mode_값        check (mode in ('lyrics', 'quiz')),
  constraint cpm_범위       check (cpm is null or cpm between 1 and 1500),
  constraint accuracy_범위  check (accuracy is null or accuracy between 50 and 100),
  constraint seconds_범위   check (seconds is null or seconds between 20 and 3600),
  constraint misses_범위    check (misses is null or misses between 0 and 999)
);

-- 순위 조회를 빠르게
create index scores_quiz_idx   on scores (mode, seconds);
create index scores_lyrics_idx on scores (mode, song_id, cpm desc);

-- 보안 규칙 켜기
alter table scores enable row level security;

-- 누구나 "읽기"는 가능
create policy "누구나 순위를 볼 수 있음"
  on scores for select using (true);

-- 누구나 "새 기록 추가"는 가능 (수정·삭제는 아무도 못 함)
create policy "누구나 기록을 올릴 수 있음"
  on scores for insert with check (true);
```

> `Success. No rows returned` 가 나오면 성공입니다.
>
> 💡 **여기가 핵심입니다.** `constraint` 규칙들이 서버 쪽 방어선이에요.
> 게임 코드에서도 한 번 거르지만, 누가 코드를 우회해도 이 규칙은 못 넘습니다.
> 수정·삭제 정책을 안 만들었기 때문에 **남의 기록을 지우거나 바꾸는 것도 불가능**합니다.

### 3단계 · 열쇠 두 개 복사하기

1. 왼쪽 메뉴 맨 아래 **Project Settings**(톱니바퀴) → **API**
2. 두 가지를 복사합니다
   - **Project URL** — `https://xxxxxxxx.supabase.co` 같은 주소
   - **Project API keys** 의 **`anon` `public`** 키 — `eyJhbGci...` 로 시작하는 아주 긴 글자

> ⚠️ 그 아래 **`service_role`** 키는 **절대 복사하지 마세요.** 그건 관리자 열쇠라
> 코드에 넣으면 누구나 데이터를 지울 수 있게 됩니다. 반드시 **`anon`** 쪽입니다.

`data/ranking-config.js` 를 열어서 세 줄만 고칩니다.

### 잘 되는지 확인하기

1. 인트로 퀴즈를 한 판 완주합니다 (**패스 없이** — 패스한 판은 등록이 막혀 있어요)
2. 닉네임을 정하고 **랭킹에 등록** 클릭
3. "랭킹에 올렸습니다!" 가 뜨면 성공
4. Supabase 왼쪽 메뉴 **Table Editor → scores** 에 들어가면 방금 기록이 보입니다

**안 되면 이 순서로 확인하세요.**

| 증상 | 원인 |
|---|---|
| "랭킹 보기"가 아예 안 보임 | `enabled: true` 로 안 바뀜 / 새로고침 안 함 |
| 등록 실패 (401) | `anonKey` 를 잘못 복사 (앞뒤 공백 확인) |
| 등록 실패 (404) | `url` 이 틀렸거나 테이블 이름이 `scores` 가 아님 |
| 등록 실패 (400) | 2단계 SQL 의 `constraint` 규칙에 걸림 (정상 동작입니다) |
| 등록 실패 (403) | 3번째 SQL 의 policy 가 안 만들어짐 |

### 응원법 랭킹 켜기 — SQL 한 번 더

응원법은 기록하는 값이 달라서(성공률·성공 개수·전체 구간) **표에 칸 세 개를 더 만들어야** 합니다.
안 하면 응원법 탭에서 `400` 오류가 뜹니다. (가사·퀴즈 랭킹은 그대로 잘 됩니다)

Supabase → **SQL Editor** → **New query** 에 아래를 붙여넣고 **Run**:

```sql
-- 1) chant 모드를 허용
alter table scores drop constraint if exists "mode_값";
alter table scores add  constraint "mode_값" check (mode in ('lyrics','quiz','chant'));

-- 2) 응원법용 칸 세 개
alter table scores add column if not exists rate  int;   -- 성공률(%)
alter table scores add column if not exists hits  int;   -- 성공한 구간 수
alter table scores add column if not exists total int;   -- 전체 구간 수

alter table scores add constraint "rate_범위"  check (rate  is null or rate  between 0 and 100);
alter table scores add constraint "hits_범위"  check (hits  is null or hits  between 0 and 999);
alter table scores add constraint "total_범위" check (total is null or total between 1 and 999);

-- 3) 순위 조회를 빠르게
create index if not exists scores_chant_idx on scores (mode, song_id, rate desc);
```

> 기존 칸이나 규칙은 건드리지 않고 **더하기만** 합니다. 이미 쌓인 기록은 그대로 남습니다.

응원법 순위는 **곡별로 성공률이 높은 순**입니다. 같으면 성공 구간이 많은 쪽이 위로 옵니다.

---

### 응원법 "외치기" 랭킹 켜기 — SQL 한 번 더

응원법은 **마이크에 대고 외치는 방식**과 **키보드로 치는 방식** 두 가지입니다.
난이도가 아예 다르니까 순위를 섞으면 안 되겠죠. 그래서 **어느 방식으로 한 기록인지 적는 칸**을 하나 더 만듭니다.

안 하면 응원법 탭에서 `400` 오류가 뜹니다. (가사·퀴즈 랭킹은 그대로 잘 됩니다)

Supabase → **SQL Editor** → **New query** 에 아래를 붙여넣고 **Run**:

```sql
-- 1) 입력 방식 칸 추가 ('voice' = 외치기, 'typing' = 키보드)
alter table scores add column if not exists input text;

-- 2) 이미 쌓인 응원법 기록은 전부 키보드로 친 것이므로 그렇게 채워둡니다
update scores set input = 'typing' where mode = 'chant' and input is null;

-- 3) 이상한 값이 못 들어오게
alter table scores drop constraint if exists "input_값";
alter table scores add  constraint "input_값" check (input is null or input in ('voice','typing'));

-- 4) 순위 조회를 빠르게
create index if not exists scores_chant_input_idx on scores (mode, song_id, input, rate desc);
```

> 2번을 꼭 같이 실행하세요. 안 하면 예전 기록이 어느 쪽에도 안 나옵니다.

랭킹 화면의 응원법 탭에서 **🎤 외치기 / ⌨️ 타이핑** 을 골라서 각각 볼 수 있습니다.

---

### 인트로 퀴즈 객관식 랭킹 켜기 — SQL 한 번 더

인트로 퀴즈도 **객관식 / 주관식** 두 가지가 됐습니다.
객관식은 누르기만 하면 되니 주관식보다 훨씬 빠릅니다. 순위를 섞으면 안 되겠죠.

응원법에서 쓰던 `input` 칸을 그대로 씁니다. 거기에 `'choice'` 를 넣을 수 있게 해주면 됩니다.

**안 하면** 객관식 기록 등록이 `400` 으로 막히고, **기존 퀴즈 기록 전부가 랭킹에서 사라집니다.**
(`input` 이 비어 있어서 어느 쪽에도 안 잡힙니다)

Supabase → **SQL Editor** → **New query** 에 아래를 붙여넣고 **Run**:

```sql
-- 1) input 값에 'choice'(객관식) 를 추가
alter table scores drop constraint if exists "input_값";
alter table scores add  constraint "input_값"
  check (input is null or input in ('voice', 'typing', 'choice'));

-- 2) 기존 퀴즈 기록은 전부 주관식이므로 그렇게 채워둡니다  ★ 꼭 같이 실행
update scores set input = 'typing' where mode = 'quiz' and input is null;

-- 3) 순위 조회를 빠르게
create index if not exists scores_quiz_input_idx on scores (mode, input, seconds);
```

> `Success. No rows returned` 또는 `UPDATE 152` 처럼 나오면 성공입니다.

랭킹 화면의 인트로 퀴즈 탭에서 **🔘 객관식 / ⌨️ 주관식** 을 골라 각각 볼 수 있습니다.

### ⚠️ 무료 플랜은 7일 쉬면 잠듭니다 — 자동 깨우기

Supabase 무료 플랜은 **7일 동안 아무도 접속하지 않으면 프로젝트를 일시정지**시킵니다.
그러면 랭킹 등록·조회가 안 되고, Supabase 홈페이지에서 직접 **Restore** 를 눌러야 살아납니다.
(게임 자체는 멈추지 않습니다. 랭킹만 안 되고 가사 타이핑·인트로 퀴즈는 그대로 동작해요.)

이걸 막으려고 **GitHub 가 매주 월요일·목요일에 대신 접속해 주는 작업**을 넣어뒀습니다.

```
.github/workflows/keep-supabase-awake.yml
```

- 최대 3~4일마다 접속이 생기므로 7일 한도에 안 걸립니다. **비용은 없습니다.**
- 직접 실행해 보려면: 저장소 → **Actions** 탭 → 왼쪽에서 **Supabase 깨우기** → **Run workflow**
- 잘 돌았는지 확인하려면 같은 화면에서 초록색 체크 표시를 보면 됩니다.

> ⚠️ GitHub 는 **저장소에 60일 동안 아무 변화가 없으면** 이런 예약 작업을 자동으로 끕니다.

## 가사 타이핑 화면 보는 법

```
        샘                ← 틀렸을 때만: 원래 쳐야 하는 글자
여 기 는  삼  ㅍ  가 사 입 니 다
━ ━ ━  ━  ━  ─ ─ ─ ─ ─
```

- 칸 안에는 **내가 실제로 친 글자**가 들어갑니다. (조합 중인 `ㅍ` 도 실시간으로 보입니다)
- 글자마다 **밑줄 칸**이 있어서 띄어쓰기까지 어디를 치고 있는지 한눈에 보입니다.

| 색 | 뜻 |
|---|---|
| 초록 밑줄 + 검은 글자 | 맞게 친 글자 |
| 초록 글자 | 지금 조합 중이고, 아직까지는 맞음 |
| 빨간 글자 + 빨간 밑줄 | 틀린 글자 (칸 위에 정답 글자가 작게 뜸) |
| 회색 흐린 글자 | 아직 안 친 글자 |
| 깜빡이는 굵은 밑줄 | 지금 쳐야 할 칸 |

## 조작법

| 키 / 버튼 | 동작 |
|---|---|
| `Space` | 가사 모드: **줄을 끝까지 친 뒤** 누르면 다음 줄로 (틀린 글자가 있어도 넘어가고 정확도만 깎임) |
| 영문 대소문자 | 가사 모드에서는 **구분하지 않습니다.** `Hey` 를 `HEY` 나 `hey` 로 쳐도 맞은 것으로 처리돼요 |
| `Enter` | 가사 모드: 언제든 다음 줄로 넘기기 / 퀴즈 모드: 정답 제출 |
| `Backspace` | 가사 모드: **입력창이 비어 있을 때 누르면 이전 줄로 돌아갑니다** (글자가 남아 있으면 평소처럼 한 글자씩 지웁니다) |
| `F2` 또는 `❚❚` 버튼 | 일시정지 / 다시 재생 (**타이머도 같이 멈춥니다**) |
| `Esc` | 게임 그만두기 |
| 화면 아무 곳 클릭 | 입력창으로 포커스 되돌리기 |
| 오른쪽 위 `◐` | 라이트 / 다크 모드 전환 |

### 오디오 조작 바 (가사 모드)

- **❚❚ / ▶** — 일시정지·재생. 멈추면 노래·타이머·입력이 **모두** 멈춥니다. (쉬어가도 기록이 안 깎여요)
- **↺** — 곡이 끝까지 재생되면 이 모양으로 바뀝니다. 누르면 노래를 처음부터 다시 틉니다.
- **0:00 / 3:24** — 현재 재생 위치 / 곡 전체 길이
- **볼륨 슬라이더** — 조절한 값은 브라우저에 저장돼서 다음에도 유지됩니다.

### 실수로 줄을 넘겼을 때 — 되돌리기

타이핑하다 보면 줄 끝에서 `Enter` 를 누르는 게 반사 동작이라, 아직 다 못 쳤는데
눌러버리는 일이 생깁니다. 그럴 때 **`Backspace` 로 이전 줄로 돌아갈 수 있습니다.**

- **입력창이 비어 있을 때** `Backspace` 를 누르면 이전 줄로 돌아갑니다.
  글자가 남아 있으면 평소처럼 한 글자씩 지워집니다.
- 줄을 **덜 친 채로** 넘어가면 화면 아래에 **"줄을 건너뛰었어요 [되돌리기]"** 가
  4.5초간 떴다 사라집니다. 그 버튼을 눌러도 됩니다. (휴대폰에서 편합니다)
- 되돌리면 **치던 글자·정확도·타수 기록·노래 위치**가 모두 그 줄 시작 상태로 함께 돌아갑니다.
  그래서 다시 칠 때 기록이 두 번 세어지거나 빠지지 않습니다.

> 줄을 정확히 다 치고 넘어간 경우에는 안내가 뜨지 않습니다. (실수가 아니니까요)

## 모드 01 · 응원법 외우기

노래가 **처음부터 끝까지 멈추지 않고** 흐릅니다. 응원 구간이 뜨면 **정해진 시간 안에 정확히 쳐야** 성공입니다.
(가사 타이핑과 달리 기다려주지 않습니다 — 응원은 순간을 놓치면 끝이니까요)

화면은 세 부분입니다.

| | |
|---|---|
| **① 가사** | 노래를 따라갈 수 있게 계속 흐릅니다. **치는 건 아닙니다.** 지금 줄은 왼쪽부터 초록으로 채워집니다(노래방 효과) |
| **② 응원** | 구간이 뜨면 남은 시간 막대와 함께 글자 칸이 나옵니다 |
| **③ 다음 응원** | 앞으로 올 응원 2개를 시각과 함께 미리 보여줍니다 |

가사는 **곡의 `lyrics` 를 그대로 씁니다.** 응원법용으로 가사를 따로 적을 필요가 없습니다.

- 구간이 오기 **1.8초 전**에 미리 뜹니다.
- 응원 시각 **+3초** 안에 다 치면 성공. 못 치면 "놓쳤어요".
- **앞뒤 구간이 가까우면 자동으로 좁아집니다.** DM처럼 2초 간격으로 붙어 있는 구간이 있어서
  시간을 고정하면 겹치기 때문입니다.
- 곡이 끝나면 **성공률 · 놓친 구간 목록**이 나오고, 곡별 최고 성공률이 저장됩니다.

이 값은 `game.js` 의 `Chant` 안 `LEAD`(1.8) / `GRACE`(3.0) 에 있습니다.
실제로 쳐보시고 빠듯하거나 널널하면 이 두 숫자만 고치면 됩니다.
`LEAD` 는 "몇 초 전에 뜰지", `GRACE` 는 "응원 시각이 지난 뒤 몇 초까지 봐줄지" 입니다.

### 응원법 넣는 법

`data/songs.js` 의 곡에 `chants` 를 추가합니다. `chants` 가 없는 곡은 목록에 안 나옵니다.

```js
chants: [
  { time: 6.51, text: "프로미스나인!" },
  { time: 11.37, text: "니 생각!" }
]
```

타이밍은 **가사와 똑같은 도구**로 찍습니다. 도구 위쪽에서 `응원법` 을 고르면 됩니다.

### ⭐ 노래 맞춰주기 (기다려주기)

노래가 너무 빨라서 못 따라가는 걸 막아주는 기능입니다. 기본으로 **켜져 있습니다.**

내가 치고 있는 줄의 **다음 줄이 시작되는 시각**에 노래가 도착했는데 아직 그 줄을 다 못 쳤으면,
**노래가 멈춰서 기다립니다.** 줄을 다 치면 저절로 다시 흐릅니다.

> 반대로 **내가 노래보다 빠를 때는 아무것도 하지 않습니다.**
> 노래를 억지로 앞으로 당기면 듣던 부분이 잘려서, 그냥 자연스럽게 흐르게 뒀습니다.

- 기다리는 동안에는 오디오 바에 **"기다리는 중…"** 이 뜹니다.
- 기록 시간은 계속 흘러갑니다. (느리게 친 만큼은 내 기록에 반영돼야 하니까요)
- 끄고 싶으면 오디오 바의 **"노래 맞춰주기"** 를 누르세요. 설정은 저장됩니다.
- 이 기능은 가사의 `time` 값을 씁니다. 그래서 타임코드를 찍어두는 게 중요합니다.

> 💡 이게 켜져 있으면 노래가 내 줄을 앞질러 갈 수 없어서, 곡이 끝까지 재생되는 건
> 내가 마지막 줄에 도달했을 때뿐입니다. 정상 동작입니다.

## 화면에 나오는 기록의 뜻

- **CPM** — 분당 타수. 한글은 자모(키를 실제로 누른 횟수) 기준입니다. (`값` = 4타)
- **WPM** — 영문 기준 분당 단어 수 (글자 5개를 1단어로 계산).
- **정확도** — 확정된 글자 중 맞은 글자의 비율.
